# Is the handcrafted-features rule right?

**Status:** Open. Unlike the other question pages here, **the claim under test was generated by this vault**, not by any source. It should be held to a higher standard of doubt accordingly.

## The Apparent Contradiction

Three held sources disagree about whether hand-built features help.

| Source | Finding |
|---|---|
| [[seq2event]] | **Degrades without** handcrafted geometric features |
| [[sig-model]] | **Degrades with** them |
| [[xsot\|Yeung & Fujii]] | A [[theory-based-modelling\|theory-based feature]] is essential (CEL 0.4876 vs 0.5545); **raw player coordinates are actively harmful** (0.5684, worse than omitting them) |

## The Proposed Reconciliation

The vault currently states, on [[representation-learning]], [[theory-based-modelling]] and the [[action-valuation-frameworks-compared|synthesis]]:

> Encode structure the representation cannot recover **and** the data cannot support learning. Encode nothing else.

A [[path-signature]] recovers path geometry by construction, so adding it is redundant. A small MLP on 2,575 examples cannot recover occlusion geometry, so adding it is informative. The disagreement is about which regime you are in.

This is tidy, and tidiness is grounds for suspicion.

## What Is Wrong With It as Stated

**The two clauses are not independent, and the rule does not say how they interact.**

"The representation cannot recover it" is a property of the *architecture*. A path signature computes iterated integrals regardless of sample size; an MLP could in principle learn occlusion geometry given enough data. So the second clause — "the data cannot support learning" — is really a statement about *where on its learning curve* a flexible model sits.

That gives a 2×2, of which only three cells have evidence:

| | Representation **can** recover | Representation **cannot** |
|---|---|---|
| **Enough data** | Redundant → harmful ([[sig-model]]) | Helpful ([[seq2event]]?) |
| **Not enough data** | **Untested** | Essential ([[xsot\|Yeung & Fujii]]) |

The empty cell is the interesting one. If a representation can recover the structure *in principle* but has too little data to do so, does the engineered feature help? The rule as written implies yes on the second clause and no on the first, and does not resolve the conflict.

**Seq2Event's cell is also uncertain.** It is classified above as "enough data, cannot recover", but nobody has established that a transformer over zone tokens *cannot* recover the relevant geometry — only that it performed worse without the features at that sample size. It may belong in the bottom-left cell, in which case it is evidence for the second clause and silent on the first.

So the rule is currently supported by **one clean case per clause and no case testing them jointly.**

## The Test

The rule predicts a **crossover**: for a fixed architecture and fixed engineered feature, the feature helps at small $N$ and stops helping — or starts hurting — as $N$ grows.

Run a data-scaling experiment on one setup, ideally [[xsot|Yeung & Fujii's]], since it has the cleanest ablation and public code:

1. Subsample and, if possible, extend the training set across a range of $N$.
2. At each $N$, train (a) MLP with the theory-based feature, (b) MLP with raw coordinates, (c) MLP with shooter features only.
3. Plot the three curves.

**If the rule holds**, curve (b) crosses above (a) at some $N$ — the network eventually learns occlusion from coordinates and the engineered feature becomes redundant. The crossover point is then an estimate of "the data cannot support learning it" in actual sample sizes, which would be far more useful than the qualitative rule.

**If (a) stays above (b) at every $N$ reachable**, the first clause is doing all the work and the second is decorative: the feature helps because the architecture cannot express the geometry, not because data is scarce.

**If (b) never approaches (a) even at large $N$**, the theory feature is contributing something the network cannot learn at any scale, which would be a stronger claim for [[theory-based-modelling]] than the rule makes.

A complementary check: run the same sweep on [[sig-model]]. The rule predicts handcrafted geometry hurts at *every* $N$ there, since the representation already contains it. A crossover in the opposite direction would falsify the reconciliation outright.

## What Would Change

**If a crossover exists and is locatable** — the rule becomes quantitative and actionable: *below roughly this sample size, encode; above it, do not*. That is a genuinely useful piece of practical guidance and applies well beyond football.

**If no crossover exists** — the rule is wrong, the three findings need a different reconciliation, and three vault pages carry an unsupported claim.

**If the results are architecture-specific** — the most likely outcome. The rule would survive as a heuristic with the honest caveat that "cannot recover" is a property of a specific architecture and not a general fact about representations.

## Why This One Is Different

The other question pages document gaps the literature left. This one documents a claim the **vault invented** to reconcile sources that never addressed each other.

That has two consequences. It is more likely to be wrong, because it was constructed to fit three points and was never tested against a fourth. And nobody else will ever test it, because it exists nowhere but here — the same structural reason as [[observed-versus-optimal-decisions]] and [[within-season-variation-noise-or-signal]], where the claim emerged from holding sources together rather than from any one of them.

Synthesis produces hypotheses cheaply and validates them not at all. Flagging which vault claims are *generated* rather than *extracted* is worth doing more systematically than the `provenance` field currently manages — an `inferred` percentage does not distinguish "reasonable gloss on a source" from "novel claim invented here."
